# Template Check

## 1. Objective

Evaluate existing portfolio templates and references against the approved **Muhammad Taha Portfolio** requirements.

The final website will **not be a direct template adaptation**. It will be a new UI/UX system influenced primarily by:

1. **Majd — Framer**
2. **Solio — Framer**

The selected references will inform composition, spacing, portfolio storytelling, typography hierarchy, interaction patterns, and visual rhythm.

The final implementation will combine those references with the approved Muhammad Taha design system, sitemap, functionality, accessibility requirements, and admin architecture.

**Majd**
→ primary structural and editorial influence

# 15. Public UI Rules

The final public interface must preserve:

### Color

* Background: `#080808`
* Secondary background: `#111111`
* Surface: `#171717`
* Primary text: `#F5F5F5`
* Secondary text: `#A3A3A3`
* Muted text: `#666666`
* Border: `#262626`
* Hover border: `#404040`
* Accent: `#8B5CF6`
* Accent hover: `#A78BFA`

### Typography

* Inter for primary typography
* JetBrains Mono for technical information
* Large editorial headings
* Tight heading line-height
* No gradient text
* No text shadows

### Layout

* Maximum width: 1440px
* 32px desktop padding
* 20px mobile padding
* 12-column desktop grid
* Asymmetric layouts
* Large whitespace
* Large project imagery
* Thin dividers

---

# 16. Project Presentation Rule

Projects are the primary proof of capability.

Do not use a conventional SaaS card grid.

Preferred structure:

```text
01 / PROJECT

[ LARGE PROJECT IMAGE ]

PROJECT NAME

Short project/value statement.

Technology · Technology · Technology

View project →
```

Projects should alternate composition:

* 7/5
* 4/8
* 7/5
* 5/7

depending on page and content.

---

# 17. Motion Rules

Motion should reinforce the Majd/Solio-inspired smoothness without becoming decorative.

### Entrance

* Opacity: 0 → 1
* Translate Y: 24px → 0
* 600–900ms

### Headings

* Masked vertical reveal

### Images

* Opacity
* Translate Y
* Scale around 1 → 1.02/1.03

### Hover

* 150–300ms

### Buttons

* Maximum movement: 4–6px

### Avoid

* Excessive rotation
* Continuous flashy animations
* Large particle systems
* Excessive parallax
* Neon effects
* Gaming-style transitions

---

# 18. Responsive Rules

## Mobile <640px

* One-column layout
* H1: 48px
* 20px horizontal padding
* No magnetic interactions
* No mouse-follow
* Minimal 3D
* Reduced motion
* Large project imagery
* Stacked CTAs
* Vertical experience timeline
* Mobile navigation overlay

## Tablet 640–1023px

* Simplified grid
* Reduced motion
* Reduced 3D
* Two-column layouts only where comfortable

## Desktop 1024–1279px

* Editorial grid
* Medium 3D
* Full interaction system

## Large desktop 1280px+

* Full 12-column composition
* Full asymmetric layouts
* Enhanced motion
* Mouse-follow 3D
* Magnetic CTA interaction

---

# 19. Accessibility

The final implementation must include:

* Semantic HTML
* Correct heading hierarchy
* Keyboard navigation
* Visible focus states
* Accessible form labels
* Accessible validation errors
* Descriptive image alt text
* Decorative images using empty alt attributes
* Reduced-motion support
* No essential information contained only in animation or 3D
* 3D fallback for unsupported/reduced-motion environments

Focus style:

```text
2px solid #8B5CF6
3px offset
```

---

# 20. Performance

Loading priority:

```text
1. Essential content
2. Typography
3. Critical imagery
4. UI
5. Motion
6. 3D enhancement
```

3D must never delay essential portfolio content.

The 3D layer must be independently removable.

Fallback levels:

```text
Full 3D
↓
Reduced 3D
↓
2D atmospheric visual
↓
No visual enhancement
```
